# Lumina production and editable delivery

Read this before generating product masters, boards, video, voice, thumbnails, or an editor timeline. Apply [model-routing.md](model-routing.md) for version/duration routes and [assets-and-voices.md](assets-and-voices.md) for lifecycle, auditions, and first-appearance bindings.

## Product lock

Import actual authorized product media into Lumina Canvas and verify the ready asset. Create `PM01` as the canonical product master. It should capture the approved SKU/variant, shape, proportions, finish, color, logo/label placement, controls/ports, packaging, and only visibly evidenced open/closed or on/off states. Never manufacture an unseen lid-opening, cream/paste, dispensing, or efficacy demonstration from a static packshot.

Create `WM01` only when a neutral geometric sheet adds value. Apply the Locked/Derived/Unknown classification from `product-research.md`. Link all product-dependent images and clips to the exact `PM01`/`WM01` revision. A generated approximation that fails a material identity check cannot be used as the hero product.

For cast or hands, keep identity, skin details, wardrobe, nail/accessory state, hand dominance, and product scale consistent. Obtain permission for supplied likenesses. Do not imitate a public figure or unlicensed creator.

## Scene and storyboard assets

Prepare the product master, evidenced packaging/variant states, recurring character/hand appearance, necessary props/scenes, and independent voice auditions for all speaking roles. Show actual ready visuals and playable voice auditions before resolving Product and Visual Lock Review. Record readiness and binding separately in the Asset Register.

Use image-conditioned editing/generation only when the real native tool accepts the imported asset and the use is authorized. Record actual asset handles and settings. If conditioning is unavailable, use the approved board as descriptive guidance and disclose the limitation; do not claim the product reference was attached.

Keep generated backgrounds free of important small copy. Use separate editor text for price, discount, coupon, claim qualifiers, CTA, and disclosure.

## Shot production table

Save a complete readable table with these columns:

| Column | Content |
|---|---|
| Scene / Shot ID | Stable shot and module ID |
| Start / End | Continuous cumulative global time; local request interval where needed |
| Retention job | Hook, setup, escalation, proof, payoff, or CTA |
| Visible action | Subject, product state, action, spatial relationship, visible result |
| Product truth / proof | Verified feature or evidence demonstrated; source ID |
| Dialogue / VO | Speaker → listener, exact measured line, cue, intent, reaction/pause, VO asset ID or none |
| On-screen text | Exact editable title, qualifier, disclosure, CTA |
| Camera / format | Shot size, angle/motion, ratio, resolution, safe-area note |
| Sound | Dialogue, effects, ambience, music intention |
| Continuity / inputs | Product/character/voice/prop/scene revisions, actual binding slots, evidenced use state, previous/next handoff |
| Generation unit | Version, base/extension/legacy segment, source video handle, global/local time mapping |
| Variant role | Shared body or H/P/CTA/thumbnail module |

Read back the full table before Ad Production Review. Timing must cover every required title, action, pause, joke beat, and CTA without overlap or unexplained gaps.

## Native generation

1. Inspect actual tools and follow the selected route in [model-routing.md](model-routing.md): 2.5 native 4–30 second base, 45/60 seconds via native extension; explicit 2.0 legacy segments at most 15 seconds. Verify resolution, ratio, duration, source-video ports, and reference/audio controls. Unsupported capability requires a stated limitation and one concrete alternative decision, not a silent substitution.
2. Compile continuous timestamps and whole-scene conversation into the selected generation unit. A storyboard cut is not automatically a new generation task. Preserve the listener's reaction and the next line's motivation; keep approved pauses and punchlines.
3. Bind ready product, character, scene, and independent voice handles in first-appearance order through real ports. Record the exact reference mapping and submission revision. Prompt-only references are not attachments.
4. For a native extension, inspect the ready predecessor's final state and use its actual source-video handle. Preserve screen geography, product state, speaking role, voice identity, and unfinished action. Check whether output is cumulative or extension-only before editing.
5. Observe each accepted task and actual playback. A completed status alone does not establish lip sync, correct product behavior, readable detail, or audible sound. Mark unavailable inspection as not inspected, not passed.
6. Separate generated background music from intended dialogue, effects, and ambience where supported. Do not mute the whole mix and call it clean. Final music belongs on an editable editor track.
7. Repair the smallest supported failed unit and actual dependents only. Query accepted or unknown jobs before resubmission. Do not drop required proof/CTA shots to hide failure, or render extra concepts/variants beyond scope. After two failed repair attempts for the same issue, save the blocker and propose a targeted simplification before spending on more attempts.

## Technical QC before editing

Inspect each actual ready unit:

- correct product model/variant, geometry, color, logo/label, controls, scale, and state;
- no morphing, duplicate parts, impossible use, unsafe handling, or unapproved packaging text;
- intended action and proof visible, with no stronger implied claim than the evidence supports;
- correct actor/hand continuity, gaze, contact, wardrobe, props, and screen direction;
- target duration, ratio, resolution, usable framing, clean first/last frames, and safe space for editor text;
- actual duration and complete dialogue/action/pause;
- speech, effects, ambience, and lip sync where required; no unintended music or doubled sound;
- no generated small text relied upon as a price, claim, disclosure, or CTA.

Mark raw output, prepared output, technical QC, and user approval separately.

## Native Video Editor

Open or reuse the real editor project. Read its latest state before every mutation and preserve user changes, locks, and unrelated tracks.

1. Import only current QC-ready assets and confirm actual media readiness.
2. Assemble the selected native master or legacy segments with explicit source ranges; preserve continuous native output and use cuts only where the approved edit requires them. Do not duplicate a base clip already included in a cumulative extension. Keep picture, dialogue/effects, final music, captions, titles/disclosures, and CTA on separate supported tracks.
3. Add the selected hook/payoff/CTA modules according to the variant manifest. Derive variants from the same approved master instead of rebuilding unrelated spans.
4. Fit authorized/original music to the comic rhythm using markers observed from actual playback or waveform. Never invent BPM. Duck it under speech and essential effects; preserve the pause before a punchline when useful.
5. Create captions from actual final speech timing. Recalculate after trims, speed changes, or module swaps. Avoid duplicate burned-in and native captions.
6. Place titles, exact claims, prices, qualifiers, legal disclosures, coupon codes, and CTA as editable text. Check spelling, contrast, safe areas, and dwell time on a phone-sized preview.
7. Save and preview the complete revision. Check first frame, hook handoff, proof, punchline, CTA, every cut, all audio, and final frame. A contact sheet cannot prove timing or sound.

Use the same project for revisions. A changed revision invalidates its previous final approval.

## Export set

After exact revision approval, export only the approved scope. Prefer a broadly playable MP4 when actually supported, without inventing codec controls. Verify the downloaded/exported artifact rather than the editor acknowledgment.

When available, deliver:

- captioned master;
- clean master without burned-in captions/text when requested;
- approved hook/CTA variants;
- thumbnail candidates;
- editable editor project/draft;
- SRT/VTT or native captions;
- Product Evidence Sheet, claim map, shot table, and variant manifest.

Use filenames such as `product_campaign_market_ratio_duration_V1_H-A_ED-v3.mp4`. A cloud draft link, queued export, expired link, or fabricated filename is not delivery.
